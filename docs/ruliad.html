A New Kind of Science, Under Univalence

Avik Jain · avikj@berkeley.edu

Wolfram's programme rests on sentences that have until now been read as programme rather than as mathematics. Seven of them are taken verbatim here, across five years of writing, and each is held to a machine-checked term. Nothing is argued by simulation and nothing is asserted of a rule class: each sentence names a theorem, and the theorem's witness is exhibited at named points.

The development sits at the smallest scale that is not degenerate — a unary substitution system with two updating events, append one cell and append two, whose multiway evolutions between fixed endpoints form an indexed inductive family. Two events, one branch point, one merge, two coordinate systems. Every constructor is reachable by hand and every refutation lands on a named collision.

Coordinatization is a path and its transport computes (1.3); the merge is a truncation whose cost is a computed object (3.4) and which has no section, so route information provably cannot be reconstructed (4.3); the interchange of co-initial events converges by refl (2.2); the advantage of proof is the universal quantifier (5.2); the merged state is one eme, constructed (6.3); purpose ranks nothing inside the ensemble it selects (7.2) and a living step refuses to descend to its marginals (7.5); and causal invariance is not needed for the observer to have a time and a law (8.2). One term inhabits the conjunction of the seven (9.1).

Every boxed term below is verbatim, carries its own import lines, and compiles on its own against Cubical Agda — Agda 2.8.0, agda/cubical v0.9, --cubical --guardedness --safe --no-import-sorts, no postulates and no holes. A green check is the theorem, not a report of one.

0. The system

Definition 0.1 (the two updating events). A state is a unary string, read as its length. The two updating events append one cell and append two:

event₁ n = suc n
event₂ n = suc (suc n)

This is a substitution system in the sense of A New Kind of Science, at the smallest size that still branches.

Definition 0.2 (multiway evolution). An evolution from a to b either halts or applies one of the two events and continues:

data Evolve : ℕ → ℕ → Type where
  halt : (n : ℕ) → Evolve n n
  ev₁  : {m n : ℕ} → Evolve (event₁ m) n → Evolve m n
  ev₂  : {m n : ℕ} → Evolve (event₂ m) n → Evolve m n

The endpoints are indices, so two evolutions between the same endpoints inhabit the same type and can be compared directly. Distinct evolutions between fixed endpoints exist and are separated by a computed invariant (3.2), never assumed distinct.

Remark 0.3 (what the scale buys). The four phenomena of the 2021 essay all appear here: two coordinate systems, one branch point, one merge, and one reconvergence. Nothing below is a claim about rule classes or about what large systems do — each statement is about this system, and each is checked. What generalises is the shape of the argument, not an extrapolation from a simulation.

1. Coordinatization is a path

Sentence 1.1 (W1, The Concept of the Ruliad, 2021). “Each [computational system] can be thought of as defining a different coordinate system for describing the ruliad … each will ultimately lead to the same limiting object.”

This is univalence, used as Voevodsky built it. It is the sentence of Wolfram's that only univalence can hold, because it identifies presentations while refunding, through transport, everything the identification would otherwise owe.

Theorem 1.2 (one path of structured systems). The same system presented in tape coordinates and in number coordinates is connected by a single path in the type of systems — carrier together with both updating events:

System = Σ[ S ∈ Type ] (S → S) × (S → S)

coordinateChange : tapeSystem ≡ numberSystem

Proof. The coordinate change Tape ≃ ℕ is the length function with its inverse, and ua turns it into a path of carriers. The two event components of 0.1 ride over that path by ua→, and the commuting datum in each is refl, because the coding function sends cell to suc definitionally. ∎

Corollary 1.3 (three clauses, three corollaries). 1.1’s three clauses discharge separately.

First, every property of systems crosses the coordinate change by transport, with no re-proof: the interchange law, proved in tape coordinates by refl, is delivered in number coordinates by subst. Second, the emulation that “moves” between coordinate systems is not a map postulated beside the identification — it is the path's own transport, and it computes to the coding function, by uaβ. In cubical type theory univalence is a theorem with computational content, which is the entire difference between citing an equivalence and running one. Third, “the same limiting object” is not agreement-after-inspection but contractibility: the space of coordinatizations of the fixed carrier, each carrying its own identification, is a point. ∎

No coordinate system is privileged, and the privilege's absence is a contraction, not a convention.

2. The interchange converges by refl

Sentence 2.1 (W4, The Concept of the Ruliad, 2021). “Causal invariance can be thought of as being associated with paths of history that diverge, eventually converging again.”

Theorem 2.2 (divergence with exhibited reconvergence). From every state the two updating events diverge — one cell apart after one event — and both orders complete to the same state three cells on — the convergence 2.1 names — with the endpoint agreement definitional:

bothOrdersConverge : (m : ℕ) → Evolve m (suc (suc (suc m)))
                             × Evolve m (suc (suc (suc m)))
bothOrdersConverge m = ev₁ (ev₂ (halt _)) , ev₂ (ev₁ (halt _))

Proof. By indexing (0.2) the two interchanged runs inhabit the same type, with no transport and no path algebra: both components are exhibited and the agreement is by indexing. ∎

Stated exactly, what is checked is endpoint agreement of interchanged co-initial updating events — the convergence the sentence names, and no more. The stronger statement is already in the corpus and is cited rather than re-proved: pointwise pairwise commutation makes every permutation of a run agree on every source state, and any observed order-dependence localises a state outside the image of the observation.

3. The merge is a truncation

Sentence 3.1 (W2, The Concept of the Ruliad, 2021). “Whenever we said that two paths in the ruliad ‘merge’, that's really just saying that we treat the outcomes as equivalent.”

The merge is propositional truncation, and its cost is a computed object.

Proposition 3.2 (the branches are distinct). The two evolutions from 0 to 3 that 2.2 produced are distinct, by an invariant that reads the first updating event.

Proof. firstEvent returns true on ev₁ and false on ev₂; cong firstEvent on a supposed path gives true ≡ false. The distinction is computed, not stipulated. ∎

Proposition 3.3 (and merged). In the observer’s single thread ∥ Evolve 0 3 ∥₁ the two runs of 3.2 are equal, by the squash — so the merge 3.1 describes is real, and really lossy.

Theorem 3.4 (the branchial pair is the fibre content). The loss is exhibited as two distinct residents of the fibre of the merge over the one merged point.

Proof. branchialPair is (route₁ , refl) and (route₂ , squash₁ _ _) in Σ[ r ] (merge r ≡ merge route₁), and their distinctness is 3.2 under cong fst. ∎

Branch structure is not what a finer observer would see; it is the fibre of the coarser observer's map, and it is computed. The same statement holds in the corpus for a reversible process calculus, where the scheduler is forbidden to merge.

-- 1 · the multiway system: two updating events on unary strings.

-- the ℕ coordinate system: a state is the string's length; the two
-- updating events append one cell and two cells.
event₁ event₂ : ℕ → ℕ
event₁ n = suc n
event₂ n = suc (suc n)

-- a multiway evolution from a to b: at each state, either halt or
-- apply one of the two updating events and continue.
data Evolve : ℕ → ℕ → Type where
  halt : (n : ℕ) → Evolve n n
  ev₁  : {m n : ℕ} → Evolve (event₁ m) n → Evolve m n
  ev₂  : {m n : ℕ} → Evolve (event₂ m) n → Evolve m n

-- 2 · W4: divergence with exhibited reconvergence, endpoints refl.

-- from every state m the two orders of the two events diverge after
-- one event and reconverge at m+3; both completions are exhibited and
bothOrdersConverge : (m : ℕ) → Evolve m (suc (suc (suc m))) × Evolve m (suc (suc (suc m)))
bothOrdersConverge m = ev₁ (ev₂ (halt _)) , ev₂ (ev₁ (halt _))

-- 3 · W1: coordinatization is a path, and there is one limiting object.

-- the second coordinate system: the unary tape itself.
data Tape : Type where
  blank : Tape
  cell  : Tape → Tape

-- the two updating events, in tape coordinates.
write₁ write₂ : Tape → Tape
write₁ t = cell t
write₂ t = cell (cell t)

-- the coordinate change, an equivalence by two inductions.
toNumber : Tape → ℕ
toNumber blank    = zero
toNumber (cell t) = suc (toNumber t)

toTape : ℕ → Tape
toTape zero    = blank
toTape (suc n) = cell (toTape n)

toNumber-toTape : (n : ℕ) → toNumber (toTape n) ≡ n
toNumber-toTape zero    = refl
toNumber-toTape (suc n) = cong suc (toNumber-toTape n)

toTape-toNumber : (t : Tape) → toTape (toNumber t) ≡ t
toTape-toNumber blank    = refl
toTape-toNumber (cell t) = cong cell (toTape-toNumber t)

coordinates : Tape ≃ ℕ
coordinates = isoToEquiv (iso toNumber toTape toNumber-toTape toTape-toNumber)

-- a system is a carrier with its two updating events.
System : Type₁
System = Σ[ S ∈ Type ] (S → S) × (S → S)

tapeSystem numberSystem : System
tapeSystem    = Tape , write₁ , write₂
numberSystem = ℕ    , event₁ , event₂

-- W1 AS A TERM: the two coordinate systems are ONE PATH in the type
-- of systems.  The carrier path is ua; the event components ride over
coordinateChange : tapeSystem ≡ numberSystem
coordinateChange i =
  ua coordinates i ,
  ua→ {e = coordinates} {B = λ i → ua coordinates i} {f₀ = write₁} {f₁ = event₁}
      (λ t → ua-gluePath coordinates refl) i ,
  ua→ {e = coordinates} {B = λ i → ua coordinates i} {f₀ = write₂} {f₁ = event₂}
      (λ t → ua-gluePath coordinates refl) i

-- consequently every property of systems crosses the coordinate
-- change by transport, with no re-proof.
propertiesCross : (P : System → Type) → P tapeSystem → P numberSystem
propertiesCross P = subst P coordinateChange

-- instantiated: the interchange of the two events, proved in tape
-- coordinates by refl, is delivered in number coordinates by subst.
writesCommute : (t : Tape) → write₁ (write₂ t) ≡ write₂ (write₁ t)
writesCommute t = refl

eventsCommute : (n : ℕ) → event₁ (event₂ n) ≡ event₂ (event₁ n)
eventsCommute =
  propertiesCross (λ (S , e₁ , e₂) → (s : S) → e₁ (e₂ s) ≡ e₂ (e₁ s))
                writesCommute

-- the emulation that "moves" between the coordinate systems is the
-- path's own transport, and it computes to the coding function.
transportComputes : (t : Tape) → transport (ua coordinates) t ≡ toNumber t
transportComputes = uaβ coordinates

-- and "the same limiting object": the space of coordinatizations of
-- the fixed carrier, each carrying its identification, is a point.
oneLimitingObject : isContr (Σ[ S ∈ Type ] (S ≃ ℕ))
oneLimitingObject = EquivContr ℕ

-- 4 · W2: the merge is a truncation, and the branchial pair is its
--        fibre content.

-- two evolutions 0 → 3: one-then-two, and two-then-one.
route₁ route₂ : Evolve zero (suc (suc (suc zero)))
route₁ = fst (bothOrdersConverge zero)
route₂ = snd (bothOrdersConverge zero)

-- the invariant that reads the first updating event.
firstEvent : {a b : ℕ} → Evolve a b → Bool
firstEvent (halt _) = true
firstEvent (ev₁ _)  = true
firstEvent (ev₂ _)  = false

-- the branches are DISTINCT, by the invariant --
routesDistinct : ¬ route₁ ≡ route₂
routesDistinct p = true≢false (cong firstEvent p)

-- and MERGED in the observer's single thread.
merge : {a b : ℕ} → Evolve a b → ∥ Evolve a b ∥₁
merge = ∣_∣₁

merged : merge route₁ ≡ merge route₂
merged = squash₁ _ _

-- the branchial pair: two distinct residents of the fibre of the
-- merge over the one merged point.
branchialFibre : Type
branchialFibre = Σ[ r ∈ Evolve zero (suc (suc (suc zero))) ]
              merge r ≡ merge route₁

branchialPair : branchialFibre × branchialFibre
branchialPair = (route₁ , refl) , (route₂ , squash₁ _ _)

branchialPairDistinct : ¬ fst branchialPair ≡ snd branchialPair
branchialPairDistinct p = routesDistinct (cong fst p)

4. The bounded observer, and the refusal of repair

Sentence 4.1 (W3, The Concept of the Ruliad, 2021). “Because we are computationally bounded observers who imagine a certain coherence in their experience, there are strong constraints on what kinds of equivalence classes we can use.” The same equivalencing is Observer Theory (2023): “a large set of possible inputs, a much smaller set of possible outputs”.

The constraint is quantified, and the repair is refuted.

Theorem 4.2 (every consumer answers equally). Any observer that reads only the merged thread — any g : ∥ Evolve 0 3 ∥₁ → X, for every X at every universe level — returns equal answers on the two branches.

Proof. cong g applied to 3.3. The quantification is over all types at all levels, so no choice of target recovers the branch. ∎

Theorem 4.3 (the merge has no section). No selector reads a run back out of the thread.

Proof. A section sel with sel (merge r) ≡ r gives route₁ ≡ route₂ by composing that equation at both routes across 3.3, contradicting 3.2. ∎

Equivalencing is many-to-one with the many exhibited, and the one-to-many direction is refuted, not merely absent. This is computational irreducibility in its proof-relevant form: the outcome — the endpoint, and even the whole merged thread — does not determine the run, so route information must be carried, since it provably cannot be reconstructed. The corpus proves the same for derivations, where soundness factors through the truncation and the truncation is strict; for denotations, where full abstraction is the statement that the denotation is the truncation; and for program synthesis, where pruning by observational equivalence collapses a fibre that is constructed and unbounded.

5. The advantage of proof is the quantifier

Sentence 5.1 (W5, Towards a Theory of Bugs: The Ruliology of the Unexpected, July 2026). “We don't get any fundamental advantage by trying to make a proof rather than just running the Turing machine — in both cases we have to expend a potentially unbounded amount of computational effort.”

The sentence is exactly right about each single instance and exactly wrong about their totality, and both halves are terms.

Theorem 5.2 (the term running cannot produce). Every state is reached from 0 — every evolution type of 0.2 inhabited — all of them by one induction:

reachesEvery : (n : ℕ) → Evolve zero n

Proof. Induction on n, through a lemma appending one event of 0.1 at the end of an evolution. ∎

A run exhibits one endpoint; this function is the whole family at once. The effort of proof is bounded by the induction, the effort of running is unbounded over the family, and that asymmetry is the fundamental advantage: the term is the family where the run is a point. The corpus holds the machine-scale form, where a composition theorem certifies a compound machine for every input with no induction over the compound.

Remark 5.3 (the escape is a named counterexample). The same essay's “whatever constraint we give, there'll always be machines that insidiously escape it” is this development's standing discipline read back. Every refusal here is exhibited — a candidate interrogated at named points, the collision written down — and a constraint without its exhibited escape is an unfinished theorem.

6. The merged state is one eme

Sentence 6.1 (W6, What Ultimately Is There? Metaphysics and the Ruliad, February 2026). “Equivalent states are in fact merged.” And the emes: “atoms of existence” whose “only property is distinctness”.

The February sentence is stronger than the 2021 merge — merged in the object, not treated as equivalent by an observer — and the stronger merge is the set quotient.

Proposition 6.2 (equal as data). Under co-terminality the two branches of 3.2 become equal in the quotient, by eq/ — not merely jointly present in a truncation as in 3.3.

Theorem 6.3 (one eme, constructed). The quotient of 6.2 contracts to a single point, and that point is the atom of existence 6.1 names with no property beyond its own distinctness.

Proof. [ route₁ ] is the centre, and elimProp with squash/ contracts every class onto it. The eme is constructed rather than posited. ∎

Theorem 6.4 (the stronger merge still has no section). Reading a run back out of the merged object collides with the branch distinction.

Proof. As 4.3, with 6.2 in place of the squash. ∎

Both merges are real, both lossy, and the loss is the same computed object.

--        merge has no section.

boundedObserver : {ℓ : Level} {X : Type ℓ}

noSection :

-- 1 · W5: the advantage of proof is the quantifier.

-- appending one updating event at the END of an evolution.
extendByOne : {m n : ℕ} → Evolve m n → Evolve m (suc n)

extendByOne (ev₁ r)  = ev₁ (extendByOne r)
extendByOne (ev₂ r)  = ev₂ (extendByOne r)

coTerminal : {a b : ℕ} → Evolve a b → Evolve a b → Type

equalAsData : Path mergedStates [ route₁ ] [ route₂ ]

7. Purpose, and the living step

Sentence 7.1 (W7, What's Special about Life?, November 2025). The rulial ensemble is “an ensemble of possible rules … selected to ‘achieve the purpose’”, and life is patches of irreducibility “fitted together to achieve that purpose” through bulk orchestration.

Theorem 7.2 (purpose ranks nothing inside the ensemble). Taking the purpose to be arrival, the ensemble selected to achieve it is the fibre of the endpoint, and every assessor reading only the merged achievement answers equally on all its members.

Proof. cong g applied to 6.2, for every g out of the quotient into every type at every level — proposition-valued fitness functions included, since they factor through functions. ∎

Theorem 7.3 (the ledger is general). The orchestration half of 7.1 needs one map. A joint state of two parts is a type J with projections p : J → A and q : J → B, and everything below is an officer of the single comparison ⟨p,q⟩ : J → A × B. For every joint whatsoever, the total space of the entanglement fibres is the joint itself:

Σ[ (a , b) ] fib ⟨p,q⟩ (a , b)  ≃  J

Proof. The fibre decomposition, at ⟨p,q⟩. Nothing double-kept and nothing dropped: as in 3.4, the fibres carry exactly what the marginals forgot, and summing them back recovers the whole. ∎

Proposition 7.4 (independence, entanglement, reconstruction). Independence is the comparison of 7.3 being an equivalence, and at the product joint it is definitionally the identity. Entanglement is the comparison's fibre, and both of its failures are pointed at rather than counted: over the diagonal joint the fibre at (true , false) is empty — a pair of marginal readings the whole never realises — and over the joint that outruns its marginals the fibre at the one reading holds two named points, a hidden degree of freedom the marginals jointly cannot see. On the diagonal joint either reading determines the other, the recovering function is exhibited and the commuting square is refl.

open import Cubical.Foundations.Equiv
open import Cubical.Foundations.Isomorphism using (Iso ; iso ; isoToEquiv)
open import Cubical.Foundations.HLevels using (isSet×)

open import Cubical.Data.Unit using (Unit ; tt)
open import Cubical.Data.Sigma using (Σ-syntax ; _×_ ; _,_ ; fst ; snd)

open import Cubical.Relation.Nullary using (¬_)

private
  variable
    ℓ : Level

-- 0 · the comparison map, and the general ledger.

module _ {J A B : Type ℓ} (p : J → A) (q : J → B) where

  compare : J → A × B
  compare j = (p j , q j)

  -- independence IS this map being an equivalence; entanglement IS its
  -- fibre family.  Both words name the same object from the two sides.
  independence : Type ℓ
  independence = isEquiv compare

  entanglementFibre : A × B → Type ℓ
  entanglementFibre = fiber compare

  -- the ledger: the joint is the sum of its entanglement fibres.
  -- nothing double-kept, nothing dropped — the same interval trick,
  fibreSum : Iso (Σ (A × B) entanglementFibre) J
  fibreSum = iso (λ (_ , j , _) → j)
                (λ j → (compare j , j , refl))
                (λ j → refl)
                (λ (ab , j , pth) i → (pth i , j , λ k → pth (i ∧ k)))

-- 1 · the product pole: the comparison is the identity, definitionally.

productCompare : Bool × Bool → Bool × Bool
productCompare = compare fst snd

-- Σ-eta makes ⟨fst , snd⟩ definitionally the identity, so independence
-- of the product joint is `idIsEquiv` with nothing to transport.
productIndependent : isEquiv productCompare
productIndependent = idIsEquiv (Bool × Bool)

-- 2 · the diagonal joint: an EMPTY fibre, named.

-- J = Bool, both projections the identity: the support {(t,t),(f,f)}.
diagonalCompare : Bool → Bool × Bool
diagonalCompare = compare (λ j → j) (λ j → j)

-- the excluded reading: (true , false) is a pair of marginal readings
-- the whole never realises.  A fibre point would identify true with
fibreEmpty : ¬ fiber diagonalCompare (true , false)
fibreEmpty (j , pth) = true≢false (sym (cong fst pth) ∙ cong snd pth)

-- so the diagonal joint is entangled: the comparison is no equivalence,
-- because an equivalence has an inhabited fibre over every point.
diagonalNotIndependent : ¬ isEquiv diagonalCompare
diagonalNotIndependent e = fibreEmpty (e .equiv-proof (true , false) .fst)

-- the diagonal is injective into a set, so every entanglement fibre of
-- this joint is a proposition: each door is either open or walled, and
diagonalFibreIsProp : (ab : Bool × Bool) → isProp (fiber diagonalCompare ab)
diagonalFibreIsProp =
  injective→hasPropFibers (isSet× isSetBool isSetBool) (λ pth → cong fst pth)

-- 3 · the joint that outruns its marginals: a TWO-POINT fibre, named.

-- J = Bool over the one-point parts: two globally distinct situations
-- whose every marginal reading agrees.
hiddenCompare : Bool → Unit × Unit
hiddenCompare = compare (λ _ → tt) (λ _ → tt)

hiddenTrue hiddenFalse : fiber hiddenCompare (tt , tt)
hiddenTrue  = (true  , refl)
hiddenFalse = (false , refl)

8. Causal invariance is not needed

Definition 8.1 (branch-blind). An observation o : X → V is branch-blind when it cannot tell two successors of a state apart: if o x ≡ o y and x steps to u while y steps to v, then o u ≡ o v. A law for o is a map g on readings with o x' ≡ g (o x) at every step — and a law gives branch-blindness immediately.

Theorem 8.2 (one reading, from the congruence alone). If o is branch-blind (8.1) then any two routes of the same length from states that o cannot distinguish arrive at states o cannot distinguish.

Proof. Induction on the common length, applying blindness at each step. ∎

There is no confluence premise anywhere in the statement. The standard demand made of a multiway rule is that any two branches can be brought back together; the observer's time and law do not need it. What they need is that the observation be blind to the branching, which is weaker and is checkable. And the converse direction is also exhibited: an observation with no law is given, so having a law is strictly stronger than being blind.

Remark 8.3 (the multiway does not collapse). Distinct branches of the multiway are provably unequal — 3.2 at this system — not merely not-identified — which is why a proof-relevant store keeps them. A branch is never identified with another branch, and that is a theorem rather than a convention of the encoding.

module _ {X : Type ℓ} (R : X → X → Type ℓ') where

  -- a run of exactly n steps, with the branches it took
  -- Defined by recursion on the length rather than as an indexed family: a
  route-n : ℕ → X → X → Type (ℓ-max ℓ ℓ')
  route-n zero x y = Lift {j = ℓ'} (x ≡ y)
  route-n (suc n) x z = Σ[ y ∈ X ] (R x y × route-n n y z)

  -- the observer cannot see WHICH branch was taken: equal readings in, equal
  -- readings out, for every choice of successor on either side.
  branchBlind : {V : Type ℓ''} → (X → V) → Type _
  branchBlind {V = V} o =
    {x y x' y' : X} → o x ≡ o y → R x x' → R y y' → o x' ≡ o y'

  -- ------------------------------------------------------------- the law
  -- Any two runs of the same length, from starts the observer cannot tell
  oneUtterance : {V : Type ℓ''} (o : X → V) → branchBlind o
    → (n : ℕ) {x y u v : X}
    → route-n n x u → route-n n y v → o x ≡ o y → o u ≡ o v
  oneUtterance o blind zero (lift p) (lift q) e =
    cong o (sym p) ∙ e ∙ cong o q
  oneUtterance o blind (suc n) (_ , r , p) (_ , s , q) e =
    oneUtterance o blind n p q (blind e r s)

  -- ------------------------------------------------- and what breaks it
  -- A predictor at the level of readings: one function of the reading that
  hasLaw : {V : Type ℓ''} → (X → V) → Type _
  hasLaw {V = V} o = Σ[ g ∈ (V → V) ] ({x x' : X} → R x x' → o x' ≡ g (o x))

  -- a predictor is branch-blind, so the two notions cannot come apart
  lawGivesBranchBlind : {V : Type ℓ''} (o : X → V) → hasLaw o → branchBlind o
  lawGivesBranchBlind o (g , p) e r s = p r ∙ cong g e ∙ sym (p s)

  -- Two successors of ONE state with different readings is the sharpest

    → R x x' → R x x'' → ¬ (o x' ≡ o x'')
    → ¬ (hasLaw o)
  noLaw o r s d h = d (lawGivesBranchBlind o h refl r s)
