# Hypercubical interaction machine: primitive encoding and reduction rules

Owner's specification, recorded near-verbatim. Implemented in `machine/`.

The machine uses one cubical composition operation, COMP. Everything else is a
defined program in this core:

- transport, homogeneous composition and filling;
- path composition and univalence;
- equivalence extension;
- identity application and annihilation.

An identity is executable graph data. Its generated forward and backward
programs are subnets, and they run on the same primitive interactions as
every other construction.

## 1. Conventions

The interval is `I`, with endpoints 0 and 1, reversal `¬i`, meet `i ∧ j` and
join `i ∨ j`. A path `p : x = y` is an interval abstraction `p = ⟨i⟩ p(i)`.
`p · q` means first `p`, then `q`.

A partial system `[φ₁ ↦ u₁, …, φₙ ↦ uₙ]` has extent `φ = ⋁ₖ φₖ`. Its branches
agree on overlaps.

The machine carries a current face assumption `χ`. An equation or branch is
available when its face follows from `χ`. An inconsistent face context
contains no executable input.

A displayed expression that introduces a variable creates a binder, and
repeated occurrences refer to that binder. Graph compilation preserves this
binding relation.

All construction and proof expressions are typed. Their types and boundary
conditions determine which connections are admissible.

## 2. Core syntax

Type constructors:

    Universe(level)  Pi(domain, codomain)  Sigma(domain, codomain)
    PathP(typeFamily, endpoint0, endpoint1)
    GlueType(baseType, face, partialType, partialEquivalence)
    Nat  Bool  Unit  Empty

- `codomain` abstracts over an element of `domain`.
- `typeFamily` is an interval abstraction.
- GlueType's partial type and equivalence exist under its face.
- Universe levels are retained.

Terms and eliminators:

    Lam(variable, body)  App(function, argument)
    Pair(first, second)  Fst(pair)  Snd(pair)
    PathLam(dimension, body)  PathApp(path, intervalExpression)
    Glue(glueType, partialElement, baseElement)  Unglue(glueType, element)
    Comp(dimension, typeFamily, face, tube, cap)
    Zero  Succ(predecessor)  NatRec(motive, zeroCase, successorCase, argument)
    False  True  BoolCase(motive, falseCase, trueCase, argument)
    UnitValue  UnitCase(motive, case, argument)  EmptyElim(motive, argument)
    Reference(definition, arguments)

A Reference points to an actual construction body, and unfolding it
substitutes the arguments into that body. An open reference with no body is a
neutral term, not an executable theorem oracle.

The following are definitions, not primitives:

    Coe HComp Fill ReversePath ComposePath Transport Equiv Contr IdEquiv
    PathEquiv EquivExtend Ua Handle ReadHandle ExtendHandle Cut Uncut
    Difference ContractSingleton IdentityForward IdentityBackward

## 3. Binding and substitution

Substitution is capture-avoiding, for terms and for intervals alike:

    (λx.M) N → M[x:=N]
    (⟨i⟩M) r → M[i:=r]

Substitution traverses every field that depends on the variable: interval
expressions, face formulas, system branches, type families, tubes, path
endpoints, and equivalence and contraction terms. In graph form a bound
variable is its binding connection, and connecting the argument to that
connection is the substitution.

COMP's side condition is that its extent does not mention the composition
dimension: `i ∉ FV(φ)`. The face context `χ` does not mention it either.

Binding identities, graph-node identities and SUP/DUP routing labels are
distinct. Label equality is not a proof of path equality.

## 4. Interval normalization

The interval terms form the free De Morgan algebra on the dimensions. The
laws are

    ¬0 = 1,  ¬1 = 0,  ¬¬r = r,  ¬(r∧s) = ¬r ∨ ¬s,  ¬(r∨s) = ¬r ∧ ¬s

plus the bounded distributive lattice laws. Neither `r ∨ ¬r = 1` nor
`r ∧ ¬r = 0` holds.

Canonical form is an antichain of finite conjunctions of signed atoms:

- 0 is the empty set of clauses, and 1 is the set holding the empty clause;
- join is union and meet is pairwise union;
- duplicates are removed, and so are clauses that contain another clause;
- negation is De Morgan, then renormalization;
- `i` and `¬i` may sit together in one clause.

## 5. Face normalization

Faces are generated by `⊥`, `⊤`, `(i=0)`, `(i=1)`, `∧` and `∨`. Here
`(i=0) ∧ (i=1) = ⊥`, but `(i=0) ∨ (i=1) ≠ ⊤`. Endpoint equations on compound
interval terms reduce as follows:

    (r∧s = 0) = (r=0) ∨ (s=0)     (r∧s = 1) = (r=1) ∧ (s=1)
    (r∨s = 0) = (r=0) ∧ (s=0)     (r∨s = 1) = (r=1) ∨ (s=1)
    (¬r = 0) = (r=1)               (¬r = 1) = (r=0)

A face is a normalized antichain of endpoint-literal clauses. Normalization
removes duplicates, clauses holding both `i=0` and `i=1`, and subsumed
clauses.

Entailment is the lattice order: `χ ⊢ φ` iff `χ ∧ φ = χ`, which means every
clause of `χ` contains a clause of `φ`.

`∀i.φ` is the largest face below `φ` that does not mention `i`: discard every
clause mentioning `i`. For example, `∀i.((i=0) ∨ (i=1)) = ⊥`.

## 6. Partial systems

A system is a finite list `[(face₁, term₁), …]`, and its extent is the join of
its faces. Under `χ`:

- branches inconsistent with `χ` are removed;
- surviving terms are restricted to their faces;
- if `χ` entails a branch face, that branch gives the value.

Applying a function to a system applies it to each branch, and projecting a
system projects each branch. Substitution acts on both faces and branches.

## 7. Ordinary interactions

    App(Lam(x,M), N) → M[x:=N]       Fst(Pair(a,b)) → a     Snd(Pair(a,b)) → b
    PathApp(PathLam(i,M), r) → M[i:=r]
    p(0) → a₀, p(1) → a₁   when p : PathP(A, a₀, a₁)
    NatRec(P,z,s,0) → z    NatRec(P,z,s,Succ n) → s(n, NatRec(P,z,s,n))

BoolCase selects its branch and UnitCase its only branch. EmptyElim has no
case. A neutral argument suspends its eliminator.

## 8. The single cubical primitive

`comp^i A(i) [φ ↦ u(i)] a₀` requires:

- `A(i) : U` and `a₀ : A(0)`;
- `u(i) : A(i)` on `φ`, with `u(0) = a₀` on `φ`.

The result inhabits `A(1)` and agrees with `u(1)` on `φ`.

**Full-face rule.** If `χ ⊢ φ`, then `comp → u(1)`.

Otherwise, normalize the head of `A(i)` with `i` fresh and symbolic, and
dispatch on it:

- Pi, Sigma, PathP, GlueType, Universe, Nat, Bool, Unit and Empty each have a
  handler, given in the sections below;
- if the head is neutral, the composition stays suspended at it.

## 9. Derived operations

    hcomp^i_A [φ ↦ u] a₀ := comp^i (λi.A) [φ ↦ u] a₀
    coe(A,0,1,a) := comp^i A(i) [] a          coe(A,1,0,a) := comp^i A(¬i) [] a
    fill^i A [φ ↦ u] a₀ (r) := comp^j A(i:=r∧j) [φ ↦ u(i:=r∧j), (r=0) ↦ a₀] a₀

The filler meets its boundary: its value at 0 is `a₀`, at 1 it is the
composition, and on `φ` it is `u(r)`. There is no FILL engine; a fill
expands into the comp above.

## 10. Pi

For `A(i) = Π_{x:D(i)} C(i,x)`, take the backwards-filled argument line

    v(r) := fill^j D(¬j) [] x₁ (¬r)

so that `v(r) : D(r)` and `v(1) = x₁`. Then

    comp^i (Π…) [φ ↦ u] f₀ → λx₁. comp^i C(i, v(i)) [φ ↦ u(i)(v(i))] (f₀(v(0)))

## 11. Sigma

    a(r) := fill^i D(i) [φ ↦ π₁u(i)] a₀ (r)
    b₁ := comp^i C(i, a(i)) [φ ↦ π₂u(i)] b₀
    comp^i (Σ…) [φ ↦ u] (a₀, b₀) → (a(1), b₁)

A neutral cap is taken apart with projections.

## 12. PathP

    comp^i (PathP^j B(i,j) ℓ(i) r(i)) [φ ↦ u] p₀
      → ⟨j⟩ comp^i B(i,j) [φ ↦ u(i)(j), (j=0) ↦ ℓ(i), (j=1) ↦ r(i)] (p₀(j))

Higher cells come from repeating this rule.

## 13. Discrete types

**Unit.** `comp Unit … → UnitValue`.

**Bool.** A box whose tube is uniformly one constructor reduces to that
constructor.

**Nat.**

    comp Nat [φ ↦ 0] 0 → 0
    comp Nat [φ ↦ Succ u(i)] (Succ a₀) → Succ(comp Nat [φ ↦ u(i)] a₀)

The condition: every surviving tube branch shows the same outer constructor in
its own face context. An empty tube satisfies it vacuously. A neutral cap or
a neutral branch leaves the composition suspended.

**Empty.** There is no case.

## 14. Equivalences

    Contr(T) := Σ_{c:T} Π_{x:T} (c = x)
    Equiv(X,Y) := Σ_{f:X→Y} Π_{y:Y} Contr(Σ_{x:X} f(x) = y)

IdEquiv has centre `(y, refl)` and contraction
`⟨i⟩(p(¬i), ⟨j⟩p(¬i ∨ j))`. Then

    PathEquiv(A) := coe(i ↦ Equiv(A(0), A(i)), 0, 1, IdEquiv(A(0)))

## 15. Extension

    ExtendContr(T, c, k, θ, u) := hcomp^j_T [θ ↦ k(u)(j)] c
    EquivExtend(e, y, θ, w) := ExtendContr(fib_{e.f}(y), e.centre(y), e.contraction(y), θ, w)

## 16. Glue

    Glue [α ↦ (T,e)] A   with T : U and e : Equiv(T,A) on α
    glue [α ↦ t] a       with e.f(t) = a on α

The reductions:

    χ ⊢ α ⇒ Glue[α ↦ (T,e)] A → T
    χ ⊢ α ⇒ glue[α ↦ t] a → t
    unglue(glue[α ↦ t] a) → a
    unglue(v) → e.f(v) on α

Unglue keeps the glue-type data it needs to identify `e`. An empty gluing
system may be kept as is.

## 17–20. Composition at Glue

The family is `G(i) = Glue[α(i) ↦ (T(i), e(i))] A(i)`, the box is
`comp^i G(i) [ψ ↦ u(i)] u₀` with `ψ` independent of `i`, and `fᵢ := e(i).f`.

    a₀ := unglue(u₀)
    a(r) := fill^i A(i) [ψ ↦ unglue(u(i))] a₀ (r);   a₁ := a(1)
    δ := ∀i. α(i)
    t(r) := fill^i T(i) [ψ ↦ u(i)] u₀ (r)            (under δ);   t'₁ := t(1)
    ω(j) := comp^i A(i) [ψ ↦ a(i), (j=0) ↦ fᵢ(t(i)), (j=1) ↦ a(i)] a₀
            so ω : f₁(t'₁) = a₁
    w := [δ ↦ (t'₁, ω), ψ ↦ (u(1), refl)]
    (t₁, p) := EquivExtend(e(1), a₁, δ ∨ ψ, w)
    a'₁ := hcomp^j_{A(1)} [α(1) ↦ p(¬j), ψ ↦ a₁] a₁
    result: glue [α(1) ↦ t₁] a'₁

## 21. Universe

    e := PathEquiv(j ↦ u(¬j)) : Equiv(u(1), A₀)        on φ
    comp^i U [φ ↦ u] A₀ → Glue [φ ↦ (u(1), e)] A₀

## 22. Univalence

    Ua(e) := ⟨i⟩ Glue [(i=0) ↦ (A,e), (i=1) ↦ (B, IdEquiv B)] B

Transport along `Ua(e)` runs through the Glue clause.

## 23. Path operations and singletons

    ReversePath(p) = ⟨i⟩ p(¬i)
    ComposePath(p,q) = ⟨i⟩ hcomp^j_A [(i=0) ↦ x, (i=1) ↦ q(j)] p(i)
    Transport(P,p,u) = Coe(i ↦ P(p(i)), 0, 1, u)
    ContractSingleton(h,k) = ⟨i⟩ (k(¬i), ⟨j⟩ k(¬i ∨ j))      for Σ_{h:T} (h = p) ≃ 1

With a variable representative the map is `(p,h,k) ↦ p`, with inverse
`p ↦ (p, p, refl)`.

## 24. Identity-agent generation

Given `p : Π_{γ:Γ} L(γ) =_{B(γ)} R(γ)`, the structural compiler builds
`c_L : Real(L,γ,y) ≃ (L(γ) = y)`, and likewise `c_R`, by contracting internal
wires. Then

    F_p(u) = c_R⁻¹(ComposePath(ReversePath(p(γ)), c_L(u)))
    F_p⁻¹(v) = c_L⁻¹(ComposePath(p(γ), c_R(v)))

Calling a generated body is ordinary application.

## 25. Cut, difference and handles

    Cut(z,u,v) = ComposePath(u, ReversePath(v))      Uncut(h) = (D(δ), h, refl)
    Difference(p,h) = ComposePath(ReversePath(p), h)
    Handle_P(x) = Σ_{r:X} P(r) × (r = x)
    ReadHandle(r,u,h) = Transport(P,h,u)
    ExtendHandle(r,u,h,s) = (r, u, ComposePath(h,s))

## 26–31. Net, agents, lowering and evaluation

**Agents.** An agent has a kind, a principal port, ordered auxiliary ports,
and literal metadata: tags, levels, interval or face forms, definition
identifiers and binder identities. Executable bodies are subnets.

**Replacement.** A replacement:

- consumes the active pair;
- preserves its external wire ends;
- creates a finite template;
- connects every fresh internal port exactly once.

Sharing goes through fans.

**Composition.** COMP first checks its face: full-face gives the tube at 1.
Otherwise the type head is demanded through COMP_HEAD.

**Dispatch table.**

| Head | Result |
|---|---|
| PI | §10 |
| SIGMA | §11 |
| PATH_TYPE | §12 |
| GLUE_TYPE | §§17–20 |
| UNIVERSE | §21 |
| NAT, BOOL | constructor inspection through demand agents |
| UNIT | the unit value |
| EMPTY or neutral | suspended |

**Lowering.**

- `LAM(x,b) ⋈ APP(r,a) → (x=a, b=r)`.
- A pattern match becomes one demand agent per match site.
- Recursion is a reference.

**Fans.** `DUP_k(SUP_k(a,b)) → (a,b)`. Distinct labels commute.

**Suspension.** A demanded neutral head suspends. Read-back reconstructs the
syntax.

## 32. Lossless observable state

    Σ_{b:B} fib_f(b)
    a ↦ (f(a), a, refl)
    (b,a,p) ↦ a
    round trip: ⟨i⟩ (p(i), a, ⟨j⟩ p(i∧j))

A contractible internal family `R(β)` may be deleted by inserting its centre.

## 33–35. Higher cells, identity rules, locality

`K(i,j) = m(p(i), q(j))`. Higher paths reuse the PathP clause. A generated
rule is `Π_β (Real(P,β) ≃ Real(Q,β))`, executed as `(β, k, u) ↦ (β, k, F_p(u))`.
Each agent has one principal port, which gives the one-step diamond and equal
lengths of terminating reductions.

## 36. Transcription boundary

The implementation consists of:

1. the core constructors and eliminators;
2. binding-preserving graph construction;
3. interval normalization;
4. face normalization, entailment, restriction and `∀`;
5. partial systems;
6. the ordinary interactions;
7. COMP dispatch;
8. the macro bodies;
9. lowering to constructor–demand interactions;
10. binding, duplication, erasure, scheduling and read-back.

Coe and HComp expand into COMP. The identity operation is
`F_p = c_R⁻¹ ∘ (q ↦ p⁻¹·q) ∘ c_L`.

## Correction: uniform, construction-generated rules

The owner's correction, superseding the Nat/Bool/Unit/Empty clauses of §§2, 7,
13 and 28.

- **No datatype is privileged.** A datatype is its construction: formation,
  constructors, eliminator, and computation identities, all given as
  constructions and identities in the same language and compiled by the same
  mechanism. A runtime tag names a construction; it adds no semantics of its
  own.
- **Tags must trace to constructions.** A specialized tag or an optimized
  implementation is admissible only as a realization of a construction. Its
  cost correspondence must be stated, not assumed.
- **Restrictions belong to occurrences.** They are reindexings `t[σ]` of
  one occurrence, never mutations of a shared cell.
- **Raw rules are stated in full.** A raw rule gives every new agent, every
  port and every wire, and the connection of every preserved boundary port.
  A program description such as "inspect the branches" is not a raw rule.
- **The architecture.** Selected generators, then constructions and
  identities, then generated subnets and rules.

Implemented in `hcm/` as follows:

- The basis is CCHM's Π, Σ, PathP, Glue, U and COMP. Nothing else is built
  in.
- An identity `p : (γ : Γ) → Path B (f a₁ … aₙ) R` qualifies when exactly
  one `aₖ = c b₁ … bₘ` and every other argument is a distinct variable of
  `γ`. A `rule p` line for it generates the agents and the interaction
  `f ⋈ c → R`. The right-hand side `p-rhs γ` is applied to the ports that
  carried the variables. The interaction counts one step, and the expansion
  of `R` counts its own.
