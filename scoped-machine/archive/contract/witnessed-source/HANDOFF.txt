# One witnessed source: complete integration view for the worker

17 October 2026. Read this as the consolidated architectural and operational contract for connecting the current machine to its cubical, boundary and work readings. It resolves the worker's proposed mixed-coordinate rewrite and the interpretation of adoption cells. It is cumulative with the attached foundation, cubical Stokes, live-cut, effect and ownership/count contracts. All earlier authorized scope remains active.

This is a specification and mathematical derivation, not a report that the worker's new chain.c or event integration has been reviewed. The latest source inspected here is the delivered V23 tree; the newer implementation is known through the worker's report. The attached finite algebra checks validate examples of this contract, not the production machine.

The governing simplification is: a generating rule supplies a typed witnessed transition; its compatible interpretations extend through composition. Existing evaluator, checker, compiler, scopes, templates, shared jobs and runtime actions remain the implementation. Their C module names are not different foundations.

1. THE SOURCE, ITS PRESENTATION, AND ITS READINGS

A context Γ includes typed declarations, dimensions, exact levels and the assumed face. The mathematical source has states S_Γ and admissible directed steps Step_Γ(s,t), with their proof premises. Finite derivations are generated by identity and composition. Higher cells compare specified derivations with specified boundary witnesses. Runtime-produced evidence has the same constructor and admission rules as supplied evidence.

The source has several compatible readings:

* semantic evidence: what typed transformation or judgment the step establishes;
* operational state: which represented local state actually changed;
* exposed boundary: which owned occurrences are available, reserved, waiting or closed;
* dependency evidence: which immutable facts and revision premises were read;
* actual work: which primitive operations were performed;
* observation/quotient: which part of the source a particular consumer reads.

A single source means these readings are linked to the same admitted rule occurrence and its composition. It does not mean one untyped record identifier must identify a reusable proof, a cache key and a unique effect occurrence. Each identity has its own equality criterion.

For any observation q:S→B, retain S ≃ Σ(b:B).fib_q(b). A quotient can erase distinctions in its own observation while their witnesses, costs and commitments remain in the retained fibre. Retention is lazy and shared. It does not require expanding every proof, enumerating every possible cell or keeping unreachable data after all owners have released it.

2. EXACTLY WHAT INITIALITY PROVIDES

The cited Agda receiver has Motion indexed by endpoints, an identity action and an action for each generating step. Its fold is determined by:

    fold_R(done) = ε_R
    fold_R(step(e,h)) = R_e(fold_R(h)).

Induction proves uniqueness. For the product receiver, the same induction gives

    fold_(R×T)(h) = (fold_R(h), fold_T(h)).

Thus a rule's semantic, boundary and work outputs should be supplied together and reused. No second traversal has to rediscover facts already emitted by that rule.

Two additional obligations matter in this machine. First, a reading of a quotient must respect the relations used by that quotient. Second, a sequential derivation fold must not blindly unfold a shared historical DAG and count a shared producer twice. Sections 7–8 give that extension explicitly. Initiality neither supplies an unknown action for a generator nor certifies a relation a receiver fails to preserve.

3. LOCAL STATES, CONTEXTUAL COMPOSITION AND DIRECTION

A concrete state contains the existing context/environment, persistent admitted facts, live mutable objects with their versions, pending jobs/tickets/frames, authority/ports, and retained work/history references. Caches and dependency revisions belong to this state when they affect future execution or cost.

Do not snapshot the global heap on every step. A local rule consumes or updates its finite declared footprint and leaves the framed context untouched. If an interior X(b) is replaced by Y(b) through an equivalence E_b at complete interface b, its action in surrounding K(b) is

    (b,x,k) ↦ (b,E_b(x),k).

The inverse and inverse laws act pointwise. Reindexing the boundary commutes with this action. This is the generic contextual replacement theorem. The interface includes any guards, versions, resource anchors and obligations that the surrounding context can use.

Pure certificate data is persistent and can be read many times. A live mutable occurrence/version is linear: an accepted transition consumes that version at most once and publishes its successor or closure. A reference-count change or ownership transfer is itself an operational change when relevant; retaining a pointer alone is not a proof of linearity.

A directed relation R:S→S→U already lives inside the current cubical type theory. A term of R(s,t) need not yield a term of R(t,s). Path equality and transport can remain reversible. Consequently this integration requires no new directed interval primitive and no change to the De Morgan algebra or CubeView's coordinate sorts. A future mathematical presentation of directed cubes would have to be a derived presentation with its full interpretation; it is not a prerequisite of the present work.

4. THE RECORDS ARE LINKED, NOT DUPLICATED INTERPRETERS

Use existing stable handles and immutable paged records. The following are semantic field requirements, not mandates for separately allocated C structs when existing records already supply them.

    Judgment:
        typed source/target or proposition, Γ, guard, exact annotations,
        evidence reference, immutable dependency/premise certificate

    Occurrence:
        stable actual occurrence identity, rule instance, execution owner,
        predecessor/local source version, successor/local target version,
        fixed-size delta or handle to a prepared delta recipe,
        read-premise references, historical support/realization links

    PrimitiveEvent:
        occurrence identity, primitive kind, owner/phase,
        source/target frame versions or local operational delta,
        bounded classification labels, bounded primitive work label

    Realization:
        judgment or macro-operation reference, entry/exit boundary,
        actual primitive-event support, ordered/causal structure,
        primitive rule interpretation certificate

    Comparison:
        comparison domain and complete parameter boundary,
        left/right derivation recipes, endpoint/connector evidence,
        higher-cell witness, realization/cost certificates where supplied

    Cut / Ticket / PreparedAdoption:
        existing live-cut records, with linked occurrence and realization
        handles; exact fields and transitions in §12

An immutable local version can be represented by a previous version plus its bounded delta and retained data references. Reconstructing a large old state is a charged lazy traversal. The working mutable representation may update in place under its existing protocol while immutable versions/deltas support historical interpretation. A version reference must not point to overwritten data whose old value is no longer recoverable under its declared retained interface.

There are four distinct keys:

1. A pure operation key: family, canonical immutable operands, relevant premises/revisions.
2. A mathematical evidence key: its typed presented construction and boundary.
3. A live occurrence identity: actual owner/namespace and fresh stable occurrence/version identity.
4. A comparison key: its domain, both recipes, the witness and boundary correspondence.

Historical metadata must not be inserted into a pure expression's semantic key merely because it was produced by a particular run. Conversely, equal pure payloads must not intern two independently accepted effect occurrences into one. Reindexing an accepted receipt transports its description and keeps its occurrence anchor; it does not execute a specialized copy of the event.

5. RULE ADMISSION AND COMMIT: THE LOCAL CONSTRUCTOR

A rule specification supplies:

    typed parameter telescope and level/guard obligations;
    persistent read premises and their validity boundary;
    live input occurrences/versions it requires;
    result and successor-boundary recipes;
    mathematical action/evidence constructor;
    operational realization and primitive-step classification;
    substitution/contextual compatibility witness.

Preparation validates or computes these fields through the existing shared operations. It may suspend and preserve work. Its result is a typed prepared object indexed by the source versions and relevant snapshot. Preparation itself performs counted primitive events even if a later installation loses a race.

Commit checks the small live ownership/version conditions on which that prepared result depends, then installs prepared handles atomically according to the existing rule protocol. The mathematical invariants are premises of this constructor. Wrapping them in one object removes repeated validation; deleting them would weaken the constructor.

Variable-size proof checks, dependency unions, event-list preparation and memory acquisition occur in retained frames before installation. Failed attempts and retries remain actual work. Semantic invalidity, resource suspension and stale operational versions remain different outcomes.

For a rule with many inputs, keep the existing reservation/commit descriptor: reserve one input per frame; one terminal descriptor state change makes the prepared result logically accepted; readers resolve reserved cells through that state; finalize one cell at a time. No unbounded list is inspected under the final commit lock.

6. PRIMITIVE EVENT PUBLICATION AND ITS COST

The authoritative work source is the primitive execution stream. A semantic beta, engine request or effect commit can additionally have a macro record referring to its primitive support. The macro and its contained primitives are not both added as independent fine work.

Each bounded native primitive has exactly one actual execution occurrence, with a sparse fixed-size work/classification label. A coarse marker such as BETA or REQUEST is a label at the corresponding actual semantic transition; it does not add the entire child cost again. If one bounded primitive legitimately increments several diagnostic categories, preserve those labels while keeping the primary primitive count separate.

Before an externally observable transition is published, its event identity and immutable descriptor must exist. Prepare fixed event slots through the existing arena/paged mechanism. Under a mutable-record lock, the state change and installation of that descriptor are part of the same publication; readers cannot see a new logical version lacking its event. Commit descriptors supply the equivalent multi-object publication rule. After unlock, append/index delivery is resumable; the committed event remains reachable from the state/descriptor even before a secondary index catches up.

For ordinary owned frame steps, the event links before/after program-counter versions and the bounded local delta. Fields of a large input, buffer or proof remain handles; do not copy them into every annotation. Primitive loops and lock-held bounded sections have the existing explicit inventory and constant expansion bound.

Event-store allocation, index maintenance and interpretation work are covered by the same accounting model. Implement the fixed event-record write as part of the bounded primitive realization; do not recursively create an event for each instruction that writes that same event. Variable maintenance is separate framed work with its own events. This is ordinary bounded implementation overhead, not an exemption for an arbitrarily large logger.

No semantic event is invented when a failed proposal performed only preparation/retry work. Those operations still have primitive events. No counted work may be left ownerless at closure. Machine/allocator/scheduler work has explicit service ownership if it belongs to no client producer.

7. EXACT ACCOUNTING AND SHARED HISTORIES

Let E be the actual primitive event identities, ordered by causality. Every finite retained history H has finite event support with its required predecessor/interface information. Logical cycles unfold into new occurrences; the finite occurrence history remains acyclic even when the computational graph contains cycles.

A wait-for edge to a pending job is not a causal edge to that job's nonexistent future result. It is a live obligation on the cut. The registration event can reference the already existing producer/request occurrence; a later delivery references the actual published result when it exists. Therefore cyclic demand remains representable without making the historical event DAG cyclic or manufacturing a completed dependency. Keep wait-for topology and committed-event causality explicitly tagged.

For exact nonnegative work weights w(e),

    W(H) = Σ_(e∈support(H)) w(e).

The same event in two references is counted once in their historical union:

    W(H1∪H2) = W(H1)+W(H2)−W(H1∩H2).

A causal dependency, a semantic proof reference, and a sequential composition edge are tagged separately. Visiting every pointer transitively and summing at every visit is not a valid implementation of this equation. In particular, RC_SEQ represents composition of mathematical evidence; it is not an instruction to pay the referenced historical producer again.

Use shared support-union jobs and memoized folds. The common-event membership reading is idempotent; exact integer summation is taken after that support is established. This is the extension from the sequential initiality theorem to retained shared occurrence histories. For a noncommutative reading, causal order is retained; reading different topological orders agrees only where the supplied independent-step coherence warrants it.

A read or observation of the history performs new work. Its query is indexed by an immutable prefix/history handle captured before that query's own events. This avoids defining the size of a history by an operation that continually enlarges the same history being measured. After the query, its work is visible in the next prefix. Concurrent prefix queries use immutable completed owner-stream prefixes with their explicit predecessor boundary; whole-machine equality checks use quiescence or an explicitly constructed consistent cut, not unrelated unsynchronized counter snapshots.

One executable consistent-cut construction is: capture a published immutable prefix root from each requested owner stream; run the existing shared union/closure operation over their retained causal predecessors, including each stream's prior-event link; return that finite downward-closed support and its exposed input/output boundary. Every predecessor was published before its dependent event, so closure follows only retained past records. Other workers may continue, but the query does not acquire their later events merely because a mutable counter changed. An owner-prefix can retain an exact cumulative shadow snapshot at the same publication point; compare its fold against that snapshot, or compare whole-machine totals at quiescence. This avoids introducing a global event-serialization bottleneck.

Each event has exactly one accounting owner; composite ownership scopes retain links to child support rather than independently charging it again. Late producer events remain owned after a requesting handle closes, as already required by ReuseScope. Closing a scope is not the end of a producer still serving other clients.

Counters are exact projections of the stream. During integration, keep independently instrumented old counters as validation shadows. At a common prefix require exact equality between each intended projection and its shadow. A discrepancy is a missing/duplicate event or classification defect. An 'unattributed' bucket is a diagnostic that must be discharged, not the final coverage rule.

Use the V23 exact-count contract: bounded updates with retained carry blocks or another proven bounded exact representation; lazy framed extraction to an arbitrary-size integer. Mathematical counts do not wrap at 64 bits. Coarse tests retain their semantic projections, while fine tests must include real new annotation/maintenance work rather than hide it to preserve an old number.

7A. THE UNIVERSAL ALGEBRA CONNECTING SHARING, CONSERVATION AND IDENTITIES

There is a useful exact compression of the preceding requirements. Let E be the actual event generators and O the exposed occurrence generators of a chosen incidence interpretation. Form

    C1 = Z^(E),       C0 = Z^(O),
    ∂[e] = [outputs(e)]−[inputs(e)].

These are finitely supported free abelian groups even when the generator collections grow without a predetermined bound. Their elements are lazy finite presentations. The typed source and its admission evidence determine which generators/compositions are permitted; linearization does not replace that admission.

For a finite historical support A, define χ(A)=Σ_(e∈A)[e]. Then

    χ(A∪B) = χ(A)+χ(B)−χ(A∩B).

An additive work assignment w:C1→M gives W=w∘χ. This proves the historical inclusion-exclusion law and explains precisely how an idempotent sharing operation feeds a non-idempotent additive measurement. χ is not a monoid homomorphism from union to addition. In particular, group-completing the idempotent union monoid as if union were ordinary addition would force its elements to vanish. Keep Boolean support, linear chains and valuation connected by this equation instead of conflating them.

Next, an additive quantity v:C0→M is conserved by every admitted generator exactly when v∂=0. Equivalently it factors uniquely through

    H0 = C0 / im ∂.

This is the universal additive conserved boundary reading. Supply the local generator equations and the entire compatible composite inherits conservation. A cash balance, a vector of independent units and another additive boundary invariant are instances of the factorization; they are not separate mechanisms. The expression H0 denotes the presented quotient and its witnesses, not a demand to compute a global normal form or enumerate the whole network before an event can run.

The admitted positive/resource cone remains part of the typed source. Integer coefficients permit subtraction when comparing histories; they do not authorize negative balances, arbitrary reverse execution or duplicate spending. For the cash instance the supplied nonnegative remainder and its arithmetic path remain admission premises even though the conserved reading factors through an abelian group.

Cycles are elements of ker ∂. Admitted comparisons supply a next boundary map ∂2:C2→C1 whose image lies in ker ∂. H1=ker ∂/im ∂2 retains the cycle distinctions that those comparisons do not identify. To add an identity comparison is to supply its higher cell and boundary relation. The retained source keeps the cell and its fibre even when a chosen reading descends through that relation.

For work w:C1→M, the obstruction to descending through the supplied degree-two relations is exactly

    w∂2 = dw.

Thus a new shortcut e comparing with a path γ has its boundary relation [e]−[γ] and work defect w(e)−w(γ), once its typed operational comparison and complete boundary have been supplied. Admitting the identity makes the semantic transformation available; it does not assert that this work defect is zero. Higher coherence gives (dw)∂3=w(∂2∂3)=0. These are the same boundary equations at successive degrees.

This explains the minimal architecture without introducing new engineered subsystems: retain the typed generators and their witnessed relations; preserve actual sharing in χ; let the chosen interpretations be folds/linear readings with the stated laws. There is no need to eagerly build matrices or a global homology database. A local generator or cell exposes its finite boundary on demand, through the existing scopes, shared operations and realization records.

8. THREE COST QUESTIONS THAT MUST REMAIN DISTINGUISHABLE

Historical work asks what events actually happened: W(H).

Incremental work from an already available history H0 asks

    W(P | H0) = W(support(P) \ support(H0)).

The complete comparison boundary includes H0 and relevant ready facts/caches. A cached prefix is a sunk cost in this incremental question; it still appears in historical work. Work already performed by a superseded consumer remains historical even when its current residual adopts a better fact.

A counterfactual comparison asks for the cost of another admitted realization. It requires that recipe and a cost certificate, or an actual separate run under the stated comparison boundary. The current run does not supply the unexecuted alternative's work merely because the result is known. A symbolic cost certificate is sufficient; the machine need not run rejected alternatives.

For example, when generic work P is already in H0, a new consumer pays its validation/adaptation A and residual realization R, with support overlap removed. It does not pay P again. If the comparison starts before P exists, the combined multi-consumer history includes P once. Both answers are exact but answer different questions. Neither rule estimates the cost of a direct implementation whose realization was not supplied.

9. RECEIPTS, PREFIXES AND THE MATHEMATICAL ACTION

Preserve the current receipt tags and their mathematical meanings: REFL, SEQ, RULE, RESTRICT, SPEC and immutable prefix restriction/specialization. Link them to their actual production/installation occurrences through realization metadata or a side relation. Do not require semantically identical receipts to become distinct merely to hold two different histories of obtaining them.

A prefix judgment is

    P=(Γ,φ,s,r,ρ,Δ): Γ;φ ⊢ s⇒*r.

Its existence does not depend on the suffix terminating. Its retained proof can be instantiated using the ordinary simultaneous map and checked boundary. The resulting fact is available under φ[σ] and has its own residual, not a borrowed old WHNF classification. Context lifting preserves the eliminator's original fields and all guards. For a bound composition dimension j, the lifted outer guard uses the specified ∀j operation.

The generic identity action remains the existing runtime term: the supplied or computed path/equivalence acts on the retained presentation through collapse, middle transport and expansion. Its execution can generate these same judgments, prefixes and actual occurrences. The proof's time of discovery introduces no compile/run distinction. Proof-use admission still preserves assumptions and rejects pending circular evidence as an unconditional proof.

10. THE CUBICAL AND CHAIN INTERPRETATIONS

Keep the existing free De Morgan coordinate algebra and simultaneous substitution. A cube map assigns each source coordinate an interval expression in the target coordinates. Endpoint restrictions compose into canonical maps. For i<j,

    d_i^ε d_j^η = d_(j−1)^η d_i^ε.

Consequently, on presented n-cells,

    ∂x = Σ_i (−1)^(i−1)(d_i^1x−d_i^0x),      ∂²=0.

Cells are typed core scopes/views or admitted presented constructions with their full boundary evidence. Derived faces come from those maps. An arbitrary matching list of corners is not itself evidence for a filler. A coordinate restriction can change dimension; it is not a degree-preserving chain endomorphism. A map of cubical families that commutes with restrictions does induce the chain map F∂=∂F.

For cochains a in an abelian coefficient group, da=a∘∂ and

    <a,∂c> = <da,c>,       d²=0.

Product orientation gives ∂(x×y)=∂x×y+(−1)^deg(x)x×∂y. The attached cubical addendum specifies exact finite sparse chains, lazy cochains, dependent coefficients, normalization and relative views using the existing shared jobs.

A state valuation v is degree zero. Conservation along e is dv(e)=0. A work reading ω is degree one. Equal work along a supplied comparison h is dω(h)=0. Positive weights on edges do not imply that ω is nonclosed. A nonzero period on a cycle also differs from a nonzero defect on a supplied 2-cell.

For varying coefficient fibres, retain the specified path transports and their square coherence; upper-face coefficients are transported to their own base vertices. The corner coherence yields ∂²=0. Do not silently choose one global scalar or exchange rate. If those coherence premises are not supplied, retain the typed dependent observation without claiming it is a flat abelian coefficient system.

The actual Agda localization module uses the set quotient of derivations by equality of their meaning. It proves factorization of meaning and obstruction to factorization of cost for its explicit examples. Keep this quotient distinct from freely inverting arrows in a category. Formal −e is signed subtraction; a performed reverse operation is another directed occurrence with nonnegative work.

11. WHAT COUNTS AS AN OPERATIONAL COMPARISON CELL

A typed mathematical equality, a substitution square, a scheduling diamond and an actual-cost comparison are related structures with different required boundaries.

A substitution of a derivation establishes

    ρ[σ]: t[σ]⇒*r[σ].

The vertical maps in its naturality square are context changes. They are not automatically paid operational paths. To read actual work from a comparison, supply its operational realizations and connectors.

For a complete-state comparison choose actual or certified recipes P:S→T_P and Q:S→T_Q, and connectors κ_P:T_P→U and κ_Q:T_Q→U when they are needed and supplied. A comparison witness with

    ∂α = [Q;κ_Q] − [P;κ_P]

then has exact defect

    Δ_α W = <ω,∂α> = <dω,α>.

The cost of the connectors is included. Some comparisons are stated only under an observation q rather than at one complete target state. Mark that domain explicitly and retain the endpoint fibres. Such a comparison proves the declared observational result; it does not establish that all future contexts or costs agree. For a continuation C the exact extension is

    Cost(P;C,S)−Cost(Q;C,S)
      = Cost(P,S)−Cost(Q,S)
        + Cost(C_P,T_P)−Cost(C_Q,T_Q).

No algorithmic discovery is demanded merely to create a comparison. An available higher witness or a proven local comparison schema supplies it. A bare pair of competing enabled rules is not automatically a cell. A chain library may represent their formal difference without pretending that it has obtained a typed comparison proof.

Higher composites of admitted comparisons use their retained witnesses. For a 3-cell k, d²ω(k)=0 constrains their signed defects. This is a coherence consequence of the cells that exist, not a rule manufacturing every requested higher cell.

12. LIVE ADOPTION AS A TYPED LOCAL TRANSITION

The following fields consolidate LIVE-CUT-ADOPTION without weakening it.

    Cut C:
      owner/slot, source s0, guard ψ, persistent resume recipe K,
      state WAITING|RESUMING|CLOSED, stable generation g,
      current residual u, q:s0⇒*u, dependencies Δq,
      ticket/subscription ownership, current occurrence/version

    Ticket T:
      retained C, captured g, residual/key requested,
      receipt/dependencies from s0, one delivery obligation

    PreparedAdoption A:
      retained C and captured (g,u,ψ), pinned immutable fact P,
      valid simultaneous map σ and exact boundary correspondence,
      required ψ ⊢ φ[σ], checked connector χ:u⇒*s[σ] if needed,
      q'=q;χ;ρ[σ], residual v=r[σ], union dependency certificate,
      validated snapshot, preallocated replacement ticket/event/launch,
      retained realization links and preparation support

Prepare A through shared jobs. A no-progress residual key is not a new adoption. Preparation preserves useful cached subresults even if installation later fails. A changed relevant revision requires revalidation. Two facts with the same old source do not supply the connector from the current residual to the new fact's source.

Installation holds the Cut lock and requires WAITING, matching g and the valid prepared snapshot. It consumes that live cut version, installs fresh g', v, q' and dependencies, and reserves the new request launch before unlock. Publish the occurrence and prepared immutable fact consistently with the state change. Enqueue after unlock. Preserve the old ticket and any producer still serving it.

Delivery consumes its own ticket once and records its actual work. If C is no longer WAITING or its generation differs, release this ticket's ownership without resuming K. Otherwise atomically claim WAITING→RESUMING, transfer K to one resume, detach the current subscription rights, and use that ticket's receipt/dependencies. A join slot fills once; its retained handles survive obsolete deliveries. Completion closes the cut; further demands create new cut occurrences.

For this operation the mathematical naturality proof supplies the instantiated evidence. The generation, guard, snapshot, connector and ownership fields make that proof applicable at this live boundary. Packaging these conditions into A is the requested simplification. The installation checks are the dynamic premises that cannot be proved once for all future mutable states.

An adoption occurrence records its actual preparation, install, request and eventual delivery support. It can reference a cost comparison certificate when one exists. It must not invent an unexecuted direct continuation or require that continuation to run just to populate a defect field. Expose separate queries for actual incremental cost and certified alternative-cost difference.

13. OVERLAPS: EXACT CLASSIFICATION AND CONSEQUENCES

The comparison class is the complete state and the stated externally chosen actions. Apply the following classifications; do not register a universal 'overlap cell' constructor that accepts any pair.

* Disjoint local transitions with compatible reads and disjoint writes: contextual commutation supplies the semantic square, up to stable renaming. Equal fine work additionally needs the native realizations to have equal weight. Shared intern tables/probe behavior can change fine work even when the semantic square commutes.
* Face restriction in two orders: equality is the canonically composed coordinate map, inherited from substitution. This is a cubical structural identity, not a second machine execution.
* Fact publication versus subscription/catch-up: the existing lock boundary partitions delivery into historical catch-up or subsequent notification, exactly once. The observable fact coverage agrees. Ready/running diagnostics and detailed administrative cost need not agree unless separately balanced.
* Fact publication versus specialization: immutable facts remain valid at their certified premises. Which available reuse edge gets selected may change actual work. Retain the selected edge and its realization; do not impose schedule-independent fine cost by deleting an alternative.
* Adoption versus delivery or advancement on the same cut: exclusive version consumption determines the winner. The loser performs its specified disposal/retry. A further comparison requires an actual typed connector or completion witness; a joining operational path is not promised merely by endpoint-value equality.
* Revision update versus fact use: historical evidence keeps its old premises. Current applicability is checked at the installed snapshot. Stale installation revalidates/retries; it cannot become valid from chain-boundary equality.
* Delivery versus client release: retained ticket/continuation ownership prevents premature free. Whether a client remains to receive the result is part of the boundary. A release does not fabricate delivery or cancel other owners.
* Two consumes of the same authority/port: only one compatible acceptance consumes that occurrence. Their different agent choices need not be equivalent. Keep the conflict and actual accepted history.

These cases establish safety/commutation under their stated premises. For any global schedule theorem, identify exactly which cells it quotients and which work reading respects them. This is how the local theorem is inherited without strengthening it by accident.

14. PORT INCIDENCE, STOKES AND EFFECTS

The execution presentation has complete states/cuts in degree zero and steps in degree one. The resource incidence presentation has anchored port occurrences in degree zero and accepted resource events in degree one. Link them by B, rather than identifying these different generators.

    B0(S) = sum of the exposed resource occurrences at cut S
    ∂res B1(e) = B0(target e)−B0(source e).

Pure transitions that leave this particular resource cut unchanged can map to zero under B1. They can still change computational obligations and have positive work in the full source. A broader boundary reading includes tickets, frames and producer obligations as well. Each reading specifies its generators and map; no port disappearance is inferred from a smaller projection.

Summing the generator equation proves the cut theorem. For a value cochain v, local conservation gives <v,∂res B1(e)>=0, hence conservation for every compatible finite composite. With an explicit interface subcomplex A, a region whose boundary lies in A defines a relative cycle. Its absolute boundary remains retained for composition and ownership.

Use EFFECT-AUTHORITY's existing generic local records and rules: prepared typed proposal, stable request identity, unique head/port occurrences, ordered reservations, terminal commit, lazy physical finalization and anchored receipts. Reservation state keeps ownership visible before acceptance; the commit descriptor determines the entire logical resource state during finalization. A scalar balance reading cannot decide whether an event was authorized.

Copying a proof or descriptor preserves its event identity and creates no new acceptance right. A new independent valid effect has a new occurrence even if its mathematical payload equals an old one's. Duplicate transport delivery rejoins the same port/request. A refund competes for the same consumption boundary as receipt; a timeout is not evidence of nonreceipt.

A network replacement supplies a composition- and emission-preserving trace map to this authority interface. Internal stuttering is allowed; an externally accepted receipt maps to its actual acceptance. The local exclusion invariant then transfers to the network implementation, and such maps compose. This specifies the interface without selecting an arbitrary protocol or pretending message signatures prove unique consumption.

15. CONTINUATIONS, OWNERSHIP AND CLOSURE

The mathematical requirement is a represented resumable state with exact ownership and a bounded transition interpretation. A continuation handle can name an occurrence; this fact alone does not force a particular stack representation.

For the desired runtime, explicit frames remain the prescribed route to arbitrary finite depth, bounded stepping, inspectable/reflected state, thread independence and deterministic disposal. Reuse existing work.c frames; lower remaining kernel call/control state into the same discipline. A frame has family/program-counter, operands, owned temporaries, awaited ticket, return destination, dependency certificate and cleanup cursor. Each frame kind has a fixed ownership table indexed by its phase.

STEP_FRAME consumes the current frame version and produces its successor or result/child request. WAIT registers its actual progress owner and exposes the waiting ticket. RESUME consumes the matching ticket/version once. DROP_FRAME releases one owned field/page or advances a cleanup cursor; it does not evaluate the unfinished mathematical program to completion. A late obsolete delivery is disposed through its retained ownership rather than resumed.

Pure private work may be retired when no live root requires it, subject to shared child ownership. Accepted external commitments remain in their port/outbox/durable boundary. Destruction is an explicit host/session operation with the established client-quiescence preconditions; it must terminate/reclaim workers and storage instead of parking abandoned native threads forever.

Logical erasure of one observer is not a negative work event. Reclamation costs actual work and preserves all surviving readings. A retained immutable summary can replace detailed data only for owners whose declared interface needs exactly that summary. Full historical reconstruction requires retaining its source data or a lossless compressed representation.

16. NATIVE COST CORRESPONDENCE

For every primitive kind, its backend implementation has a fixed bound on word operations, memory accesses and fixed-size updates. All input-sized scans/copies/proofs/exact arithmetic are retained sequences of such primitives. Address-width directories may have a backend-fixed depth; mathematical arity, levels, coefficients and counts remain extensible/exact.

Let N be actual primitive occurrences, including dispatch, event recording, joins, retries, allocation maintenance and retirement. The implementation inventory must establish

    Instr_C(h) ≤ c N(h)+d.

A two-sided constant-factor statement also needs bounded counting multiplicity per actual instruction execution. Do not inflate event counts to obtain an upper bound. The host allocation/network/device interface remains explicit; no OS latency bound follows from this instruction theorem. 17. GEODESIC CERTIFICATES AND THEIR COMPARISON DOMAIN

For a declared goal class and complete compared states, supply V with V(z)=0 at every successful target in that class and, for every admitted compared edge e:s→t,

    V(s) ≤ ω(e)+V(t).

Write slack(e)=ω(e)+dV(e)≥0. For γ:s→z,

    W(γ)−V(s) = Σ_(e in γ) slack(e) ≥ 0.

Equality along the selected path proves attainment. This is the discrete calibration/telescoping argument. A shortcut or newly usable identity belongs to that comparison relation only with the corresponding inequality or updated certificate. A comparison cell records its exact work defect; a calibration records a lower bound valid on the compared admissible transitions. Neither object requires branch-and-bound or speculative execution of alternatives. They do require their actual witnesses. 18. REFLECTION, POSING AND UNIFORM RUNTIME EVIDENCE

Keep three interfaces explicit so the common-source integration does not accidentally claim more or impose a new compile/run wall.

Resource suspension and a recursive pending claim are not obstructions. Connecting an existing constructive producer to this interface is specified by the ordinary demand protocol. All these requirements remain immediate scope. This document resolves the common-source representation and its interpretation; it does not label the latter two larger constructions complete or hand the worker an unexplained instruction to invent an inference algorithm.
